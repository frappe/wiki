# Rename the app route `/wiki` → `/wiki-app`

## Why

`/wiki` is the single most obvious route someone wants for *their own* wiki, and today the app
squats on it. The squat is not cosmetic — it is enforced in three places that together make a
Wiki Space at route `wiki` unusable:

1. `website_route_rules` rewrites `/wiki/<path:app_path>` → the `wiki` www page, so **every**
   child page of a space at `/wiki` is swallowed by the SPA.
2. `WikiDocumentRenderer.can_render()` hard-refuses `path == "wiki"` and `path.startswith("wiki/")`,
   so the reader declines those routes outright.
3. `wiki/www/wiki.html` occupies the bare `/wiki` endpoint.

`install.py` already carries the scar tissue: the default space is created at route `docs`
*"to avoid conflict with the app's base URL /wiki"*.

Moving the editor SPA to `/wiki-app` frees `/wiki` for content. This is a breaking URL change,
so it lands **before** the v3 stable release, not after.

## What

The authenticated editor SPA moves from `/wiki` to `/wiki-app`. The public reader (`/<space>/<page>`)
is untouched. No redirect from the old route (see Decisions).

## Decisions

**No backward-compat redirect from `/wiki`.** `resolve_redirect()` runs in `PathResolver.resolve()`
*before* any renderer, so a `website_redirect` on `/wiki` would permanently shadow a user's space at
that route — the exact thing this change exists to fix. v3 is not yet stable; a clean break is cheap
now and impossible later.

**Default space route stays `docs`.** Freeing `/wiki` means users *may* claim it, not that we claim
it for them. Only the stale comment in `install.py` changes.

**`wiki/www/wiki.html` is renamed, not aliased.** Keeping the file and adding
`{"from_route": "/wiki-app", "to_route": "wiki"}` would leave `wiki/www/wiki.html` still resolving at
`/wiki` — the squat survives. Frappe's `TemplatePage.set_pymodule()` maps `-` → `_` for the
controller module, so `www/wiki-app.html` pairs with `www/wiki_app.py`.

## How

### Phase 1 — tracer bullet: SPA answers at `/wiki-app`, reader accepts `/wiki`

| File | Change |
| --- | --- |
| `wiki/www/wiki.html` → `wiki/www/wiki-app.html` | `git mv` (built artifact; regenerated by `copy-html-entry`) |
| `wiki/www/wiki.py` → `wiki/www/wiki_app.py` | `git mv`; contents unchanged |
| `wiki/hooks.py:204` | `{"from_route": "/wiki-app/<path:app_path>", "to_route": "wiki-app"}` |
| `wiki/frappe_wiki/doctype/wiki_document/wiki_document.py:638` | guard → `"wiki-app"` / `"wiki-app/"` |
| `frontend/src/router.js:73` | `createWebHistory('/wiki-app')` |
| `frontend/src/router.js:93` | login redirect `/wiki` → `/wiki-app` |
| `frontend/vite.config.js:42` | `indexHtmlPath: '../wiki/www/wiki-app.html'` |
| `frontend/package.json:12` | `copy-html-entry` target → `wiki-app.html` |

Verify: `bench build`/`yarn build`, then `/wiki-app` and `/wiki-app/spaces` load the SPA; a Wiki
Space created at route `wiki` serves its pages at `/wiki` and `/wiki/<child>`.

### Phase 2 — remaining entry points into the SPA

| File | Change |
| --- | --- |
| `wiki/hooks.py:15` | `add_to_apps_screen` route → `/wiki-app` |
| `wiki/desktop_icon/wiki.json:10` | `"link": "/wiki-app"` |
| `wiki/wiki/doctype/wiki_settings/wiki_settings.js:6` | `add_web_link("/wiki-app", …)` |
| `wiki/frappe_wiki/…/wiki_document.py:305` | `get_edit_url` → `/wiki-app/spaces/{space}/page/{name}` |
| `wiki/www/github/redirect.py:37` | `/wiki-app?github_connected=1` |
| `wiki/www/github/manifest_redirect.py:40` | `/wiki-app?github_app_created=1` |
| `wiki/install.py:10` | comment now describes `/wiki-app` |

### Phase 3 — tests and docs

- ~30 `e2e/tests/*.spec.ts` files: `page.goto('/wiki…')` and `a[href*="/wiki/spaces/"]` selectors →
  `/wiki-app…`. Mechanical; `e2e/helpers/wiki.ts` comment too.
- Unit coverage for the guard: `WikiDocumentRenderer.can_render()` must **refuse** `wiki-app`
  and `wiki-app/x`, and **accept** a published page at route `wiki` — this is the regression that
  matters, and it is the one that silently reverts if someone restores the old constant.
- `ARCHITECTURE.md:36` — `/wiki` route → `/wiki-app`.

### Phase 4 — verify

- `bench --site wiki.localhost run-tests --app wiki --module wiki.frappe_wiki.doctype.wiki_document.test_wiki_document`
- `BASE_URL=http://wiki.localhost:8000 yarn playwright test` (full e2e; local job-queue load applies)
- Manual: create a space at route `wiki`, confirm `/wiki` and `/wiki/<page>` render the reader.

## Out of scope

- Public reader URLs (`/<space>/<page>`), `.md`/`llms.txt`/`sitemap.xml` crawler routes.
- The `wiki` app/module/package name — only the **URL** changes.
- Any migration patch: nothing in the DB stores the SPA base path except the standard Desktop Icon,
  which re-syncs from `wiki/desktop_icon/wiki.json` on `bench migrate`.

## Risk

Existing v3-beta bookmarks to `/wiki/...` 404 (or, once a space claims `wiki`, land on unrelated
content). Accepted — pre-stable, and the alternative negates the change.
